# Маркетинговий аналіз TokenMonitor ($TMR) → шлях до прибуткового продукту

*Дата: 08.11.2026 · джерела: живий сервіс (token-monitor-2.vercel.app), код репозиторію (112 комітів), Reddit r/solana, Token Terminal, DefiLlama, Whale Alert / CryptocurrencyAlerting прайсинг, GMGN/Axiom/Photon блоги*

> **Примітка (оновлення моделі):** після цього звіту бізнес-модель перероблена — ядро: **Owner Boost** (власники токенів платять за verified-сторінку) + Turbo/AI апгрейди + оплата криптою Solana. Актуальні деталі: `BUSINESS_PLAN_UK.md` і `PRODUCT_PLAN_UK.md`.

## 1. Резюме (Executive Summary)

**Що ви маєте:** технічно сильний, швидкий (webhook 50–150 мс) і добре протестований парсер транзакцій Solana (Pump.fun, Jupiter, Meteora, OKX, Bags, DFlow, Raydium) з live-фідом і historical-режимом.

**Проблема:** це інструмент, а не продукт. Немає акаунтів, збереження стану, push-доставки, монетизаційного шару. Користувач сам приносить Helius-ключ і получает значення, яке GMGN/Photon/BullX дають "з коробки" безкоштовно.

**Головна знахідка ринку:** уся конкуренція стискається у "трейдинг-термінал" (швидше купуй/продавай). Нішовий білий простір — **не торгівля**, а **спостереження і довіра**:
- алерти про дії dev-гаманця / LP / бандлінг-патернів → Telegram/Discord;
- white-label "live-фід прозорості" для CTO-спільнот та сайтів проектів;
- простий parsed-feed API для DIY-автоматизацій (n8n/Make/боти) та AI-агентів (MCP/x402).

Це сегмент, де платять підпискою $15–200/міс, а не 1% з угод, і де у вас є технічна перевага (латентність), яку Wh Ale Alert і старі алерт-сервіси не мають.

### 2.2 Чого критично немає (розрив проти ринку)

1. **Push-доставка**: Telegram / Discord / Email / браузерні пуші — нічого. А ринок купує саме доставку, а не фід у вкладці (Reddit: «I've tried several bots but it seems like they are not working» — надійність доставки = валюта).
2. **Стан/персистенція**: немає БД, гаманців користувача, watcher-ів, історії сесій. Кожне візит = початок з нуля.
3. **Акаунти та білінг**: ніякої аутентифікації, планів, лімітів.
4. **Whale/dev-логіка**: пороги (≥ N SOL), теги гаманців, dev-wallet tracking, bundle/insider-патерни — головні запити ринку, відсутні.
5. **Watchlist**: один токен за раз. Трейдинг-патерн = 5–30 токенів.
6. **Публікація/шерінг**: фід не можна дати посиланням або вбудувати — немає read-only share-сторінок, embed-віджета, RSS/webhook-out.
7. **Экспорт/аналітика**: CSV, агрегати (сітка buy/sell pressure, net flow), PnL.
8. **Жорстка прив'язка до Oracle**: `SOL_PRICE_USD ≈ 200` хардкод у parser — на волатильному ринку це псує "зважений SOL" і бюджети алертів.

### 2.3 Технічна готовність до монетизації

- Vercel + SSE: обмеження на тривалі з'єднання, хтрібно розуміти проксі-ліміти; для multi-tenant зовсім скоро знадобиться черга та вертикальний процес (Prob: `webhookManager.ts` — спільний стан in-memory).
- Нема rate-limit/billing-персистентності: `heliusRateLimit.ts` лише локальний.
- Висновок: до SaaS-cхеми потрібні: БД (Postgres/Upstash) + простий auth (ticket-based і targets), черга подій на Telegram-sender.

### 3.3 Реальні болі користувачів (по Reddit/статтях 2025–2026)

1. **«Dev продаває, поки графік ще зелений»** — інтерв'ю н8n: бачити вихід dev-гаманця в ту саму секунду. → алерти на dev-wallet дії.
2. **95% скам-токенів, DD manually 30+ хв** — thread про memecoin-аналізатори → автоматизація due diligence (bundles, insiders, snipers, dev-історія).
3. **Боти "не видаються"** — декілька TG-монітор-ботів «не працюють» → надійність доставки як ключова вимога.
4. **Копитрейд**: «копіювати правило smart-money-гаманцях у ту саму мить, коли вони свапають».
5. **Whale-пороги**: коли великий Cool Wallet вхід/вихід у конкретний токен (не глобальні BTC $100M алерти Wh Ale Alert).
6. **Спільноти (CTO)** хочуть показати «dev більше не в грі / має 0 продажiv» — инструменты довіри: бачити позиції dev, LP-стан, розподіл холдерів. (Ог напис у HeY Anon DAO: revival-фільтр "без dev-wallet активності" — це те, за що платять спільноти.)
7. **Швидкість вирушає стратегії** — боти конкурують на ms; ваші 50–150мс — це бренда практичний аргумент.

## 4. Конкурентний whitespace (де ви виграєте)

**Термінали (GMGN/Photon/BullX/Axiom)** — экстремальна конкуренція за 1% від угод. Їхня сліпота:
- немає публічного parsed feed API → DIY/AI-агентний сегмент голодний;
- UI перевантажені, надлишкові для "скринінгу однієї монети мого проєкту";
- ніякого white-label для спільнот;
- алертин по dev/LP слабкі або платне-в-скрині.

**Whale Alert / CryptocurrencyAlerting** — мультичейн-генерики, повільні, без pump.fun-семантики (dev sell, bonding curve, CTO-події, бандлери).

**Позиція для вас: "The transparency layer of Pump.fun / Solana" — шар довіри (обсервації), а не шарлы торгівлі.**

## 5. Пропозиції фіч (пріоритет за ROI)

### Tier 0 — найближча зона «клікабельні гроші» (2–6 тижнів розробки)
1. **Watchlist + постійні watcher-и** (3–10 токенів одночасно), збереження в БД — са основа всього платного.
2. **Telegram-бот доставки**: підписка на токен + пороги: BUY/SELL ≥ X SOL, Whale-вхід, **DEV SELL**, LP Remove (rug-алерт), big-holder або bundle-патерн. Це головна платна фіча ринку.
3. **Whale-пороговий фільтр** у фід (≥ N SOL) — передусім бо парсер уже має "зважений SOL".
4. **Share-сторінка токена** (readonly, `/token/<mint>`) — прирона база SEO (програматичні сторінки для кожного токена, як DexScreener), унікальний трафік-магніт; записує лінками в спільнотах.
5. **Виправлення SOL-price** на реальний оракул (Pyth/Jupiter price API) — інші vfod$ прямо в як партії алертів.

### Tier 1 — ніша-монетизація (1–3 місяці)
6. **Embed-віджет Live Transparency Feed** для сайтів спільнот (`<iframe>` + брендинг хоста, Powered by TokenMonitor) — белый label = самийи платоспроможний сегмент (спільноти вже купують тредінг, listings, боти).
7. **Discord-бот** для серверів проєктів (канал #live-feed, роль-alертов): дубляж TG-бот-логіки, webhooks-out.
8. **Dev-wallet Intelligence**: автоматичний детект dev-гаманця (майнер/creator/fау-payer), тег «dev кошенчна» + devа-серial-number історії по всіх його токенах (як GMGN але фокус-на-monіторинг).
9. **Historical → CSV/PnL-экспорт** + агрегати (net flow за год/день, buy/sell pressure-графік).

### Tier 2 — стратегічний ріст (3–6 місяців)
10. **Public Feed API** (REST+SSE+webhook-out) з персистентним ключем: `GET /v1/feed/{mint}?min_sol=5` — 20× простіше, ніж helius-enhanced parsing; ціль — n8n/Make/Zapier, проєкції-боти **і нова хвиля AI-агентів** (MCP-сервер + x402-мікропейменти = тренд 2026).
11. **Copy-trade Watch**: моніторинг гаманців-цілів (не виконання!) — ти спостерігаєш, а торгувати людина йде у Photon/GMGN **за вашою рефералкою** (у вас уже стоять реферал-лінки!). Двi монетизації з однієї фічі.
12. **Token-gated доступ через $TMR**: Примальниці плану за холдинг, burn-механіка «спали X $TMR → 30 днів Pro», channel-gating бот ранньо-доступом. Вихід: utility → pressure на токен.
13. **Bundler/insider-скан** на старті токену (по історії перших N блоків) + «риск-скоре» перед The фльікою — все в share-сторінці.

### Що НЕ робити
- Власний non-custodial своп/трейдинг — во разработках, юридичні ризики, пряме суперництво з Axiom/Photon.
- Мультичейн-розширення до появи доходу.

## 7. GTM (як приходити з цим на ринок)

1. **Викривчий трафік через share-сторінки / programmatic SEO** — `/token/<mint>` для кожного токену, що торгують; автоматичні «live feed» історія→DexScreener-модель. Це дешевий органіч нічого, конкуренти в алерт-сегменті цим не робят.
2. **Спільноти CTO**: обійти X/Telegram-канали про «convoy + revival» мета-токени, дати embed-безкоштовно на 2 тижні → paid. Стартовий список: тредінг CTO-субре... (pump.fun secondary, Bags, Believe revival-спільноти).
3. **Реліз на r/solana, X-трефени після історій "I built"** — у вашому форматі «webhooks, 0 polling, 50–150ms» чудово відкриває тред (рецепт: пост коду + GIF фіда у дії).
4. **Партнерська loop з терміналами**: у кожному алерті «айди гаманця → кнопка Trade on Photon/Axiom (рефералка)» — конкуренти платять вам за те, що ваш продукт веде їм volume.
5. **GitHub/DevRel**: репо з 112 комітами/тестами — це вже Dev-повага; README продає API-план, посилання на docs, швидкий start n8n-шаблон.

## 8. Ризики

- **Залежність від Helius** (ціни/ліміти) → закладіть 2 RPC-провайдера в Pro-плані.
- **Vercel/SSE обмеження** при map-tenancy → переїзд агенерацій/воркера окремо від веба (у вас вже є `server.ts` — база).
- **Циклічність мем-ринку**: підписки падають у засуху → контрактний сегмент (API для проектів/агентів) — стабілізатор.
- **$TMR-токеноміка**: burn-механіка чесна, але будь-який «наш токен погід при вірі» → обов'язково прозорий блог/документація.
- **Юридика**: ви — інфраструктура/інформація, не брокер і не фін-поради; слова «not financial advice» на share-сторінках + лость «даноє ремарка».
